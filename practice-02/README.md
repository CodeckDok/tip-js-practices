## 3. Функции, ссылки и копирование

Файл `examples/functions-and-references.js`. Прогноз до запуска и
фактический результат:

| № | Прогноз до запуска | Фактический результат | Причина |
|---:|---|---|---|
| 1 | `sum(2, 3)` → `5`; `sum("2", 3)` → `"23"` | `5`; `"23"` | `+` со строкой выполняет конкатенацию |
| 2 | `double(5)` → `undefined` | `undefined` | В стрелочной функции с телом `{}` нет `return` |

стрелочной функции.

## 4. Модель данных и функции

**Поля задачи:**
- `id` — целое безопасное положительное число, уникальное;
- `title` — строка после `trim()`, длина 1–100;
- `completed` — логическое значение, при создании `false`;
- `priority` — `"low"`, `"medium"` или `"high"`, по умолчанию `"medium"`.

**Назначение файлов:**
- `src/data.js` — экспорт `demoTasks` и данных варианта;
- `src/task-service.js` — девять функций, без `console.log`;
- `src/main.js` — демонстрационный сценарий;
- `checks.js` — сравнение фактических результатов с ожиданиями.

**Почему `id` не индекс:** индекс меняется при удалении и добавлении,
а `id` идентифицирует запись. Поиск по `tasks[id]` неверен — это индекс,
а не id.

**Почему `getTaskStats` возвращает число, а не строку:** расчёт и
отображение разделены. `progress` — число для дальнейших вычислений;
`toFixed(1)` применяется только в `main.js` при выводе.

**Какие объекты копируются при изменении задачи:** создаётся новый
массив и новый объект только для изменяемой задачи; остальные объекты
переиспользуются без изменения.

## 5. Общий демонстрационный сценарий

Вывод `node practice-02/src/main.js`:

| Этап | Всего / выполнено / осталось / прогресс | Итог |
|---|---|---|
| Исходный набор | 4 / 2 / 2 / 50.0% | Пройдено |
| Добавление id 20 | 5 / 2 / 3 / 40.0% | Пройдено |
| Выполнение id 4 | 5 / 3 / 2 / 60.0% | Пройдено |
| Переименование id 10 | 5 / 3 / 2 / 60.0% | Пройдено |
| Удаление id 1 | 4 / 3 / 1 / 75.0% | Пройдено |

**Идентификаторы итогового списка:** `[4, 7, 10, 20]`.

**Попытка добавить дубликат id 4** возвращает `{ ok: false, error:
"задача с id=4 уже существует" }`, список не меняется.

**Подтверждение неизменности `demoTasks`:** после всех операций
`demoTasks.length === 4`, `demoTasks` содержит `[1, 4, 7, 10]`,
исходные объекты не изменены.

## 7. Вывод

Освоены: ES-модули (`import`/`export`, `"type": "module"`),
разделение «данные / логика / сценарий», чистые функции без мутации
входных массивов и объектов (`filter`, `map`, spread), возврат
результатов в едином формате `{ ok, ... }` / `{ ok: false, error }`,
поверхностное копирование массивов и объектов и его последствия
(общие ссылки внутри), отладка через `node:assert/strict`.

Наиболее показательным оказался эксперимент 2: стрелочная функция с
телом в `{}` без `return` молча возвращает `undefined` — ошибка не
синтаксическая, программа «работает», но результат неверный. Второй
важный момент — spread массива копирует только верхний уровень:
`arrayCopy[0] === sourceArray[0]`, поэтому изменение вложенного
объекта видно через обе переменные. В `task-service.js` именно
поэтому при изменении задачи создаётся **новый объект** через
`{ ...task, поле }`, а не мутируется исходный.
